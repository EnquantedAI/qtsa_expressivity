# Working notes

## Model and notation

For a fixed circuit architecture, I write the state as

\[
|\psi(x,\theta)\rangle = U(x,\theta)|0\rangle^{\otimes n},
\]

where `x` is the input and `theta` contains the trainable parameters. In the current shared model the data are encoded with the ZZ, IQP or angle feature map, followed by `StronglyEntanglingLayers`.

It is useful to keep the following circuit settings explicit when comparing results:

- number of qubits;
- number of trainable layers;
- total number and shape of the parameters;
- feature map;
- entanglement pattern;
- measured wires and observables;
- backend and analytic/shot-based mode.

## Metrics

The project uses several quantities which describe different properties of the same model. I do not treat them as interchangeable.

- Haar/KL and frame potentials describe how an ensemble of circuits compares with Haar-random states or unitaries.
- QFIM describes the local geometry of the family of quantum states with respect to the trainable parameters.
- Classical FIM depends on the measurement probabilities and is the object used in Effective Dimension calculations.
- Krylov methods study the subspace generated by repeated action of a chosen operator, so their meaning depends on which operator and initial state are used.
- Gradient variance concerns the optimization landscape and is one of the standard diagnostics for barren plateaus.
- MSE and \(R^2\) describe prediction quality, not expressivity by themselves.

For a normalized pure state the convention used in the code is

\[
F^Q_{ij}=4\,\operatorname{Re}\left(
\langle \partial_i\psi|\partial_j\psi\rangle
-\langle \partial_i\psi|\psi\rangle
 \langle \psi|\partial_j\psi\rangle
\right).
\]

I currently use central finite differences for the state derivatives. This is slower than automatic differentiation, but it gives a simple reference implementation which can be checked independently of PennyLane.

The numerical rank depends on the eigenvalue threshold. Any reported rank should therefore include the tolerance used in the calculation.

## Checks used for the QFIM code

The implementation is tested on four simple states:

1. `RY(theta)|0>`, for which the QFIM is `[1]`;
2. `RY(theta_1 + theta_2)|0>`, which has two parameters but rank one;
3. two independent `RY` rotations, which give the two-dimensional identity matrix;
4. a global phase `exp(i theta)|0>`, which gives a zero QFIM.

There is also a test that rejects an unnormalised state.

## Architecture sweep

The small experiment in `qfim/experiments/` varies the number of qubits and layers. For every sampled circuit it records the QFIM eigenvalues, rank, relative rank, trace and condition number. Inputs and parameter values are generated from recorded random seeds.

Before using these results in a comparison with LED, Krylov or Haar/KL calculations, the team still needs to agree on:

- whether to use one fixed input, several fixed inputs or an average over the input distribution;
- parameter initialization ranges;
- the rank threshold;
- which circuit settings remain fixed when width or depth changes;
- a common format for saved results.

The current sweep code is only a starting point for these decisions.
